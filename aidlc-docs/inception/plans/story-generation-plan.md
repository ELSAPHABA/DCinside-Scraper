## 스토리 분해 방식 후보

### 사용자 여정 기반

작업 설정, 스크래핑, 저장, 복구처럼 사용자의 실제 흐름을 따라 스토리를 구성합니다.

워크플로 이해가 가장 중요할 때 적합합니다.

### 기능 기반

스크래퍼 기능 단위로 스토리를 구성합니다.

구현 단위와 기능 단위를 가깝게 맞추고 싶을 때 적합합니다.

### 페르소나 기반

사용자 유형별로 스토리를 구성합니다.

CLI 사용자, 라이브러리 사용자, 운영자, MCP 클라이언트가 서로 다른 방식으로 시스템을 사용할 때 적합합니다.

### 도메인 기반

검색, 게시글 상세, 댓글, `(펌)`, 저장, 운영 같은 도메인 개념으로 스토리를 구성합니다.

데이터 정확성이 가장 중요할 때 적합합니다.

### 에픽 기반

상위 에픽 아래에 하위 스토리를 구성합니다.

전체 로드맵과 구현 가능한 세부 스토리를 함께 보고 싶을 때 적합합니다.

## 확장 규칙 반영 메모

- Security Baseline: 입력 검증, 민감정보 로그 금지, 평문 Proxy Profile 경고 동작을 관련 인수조건에 포함해야 합니다.
- Resiliency Baseline: 중단점 저장/복구, 실패 처리, 로컬/단일 컨테이너 운영 범위를 관련 인수조건에 포함해야 합니다.
- Property-Based Testing: 파서, 직렬화, 중복 제거, 중단점, `(펌)` 제목 정규화 로직의 테스트 가능성을 관련 인수조건에 반영해야 합니다.
